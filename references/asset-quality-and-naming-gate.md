# Asset quality and naming gate

Apply this gate before classifying a source asset as usable evidence. Keep original files unchanged; record acceptance or rejection in the job manifest.

## Accept only evidence that can be inspected

An identity, detail, or action asset must be sharp enough to inspect the claimed feature, show the required product area without hand/prop occlusion, and retain true colour and proportions. Reject it for prompt evidence when it is heavily blurred, overexposed, strongly reflective, cropped through the needed component, compressed beyond recognition, or mixes different SKUs/variants. A beautiful lifestyle image may be `context`, but cannot prove an obscured mechanism.

For an action, the start and end state must each be visible in their own accepted frame. When either is not readable, request a replacement; do not infer the missing state from adjacent footage.

## Stable names

Copy or label selected assets in the job ledger with this form:

`<sku>__<variant>__<role>__<view-or-state>__v01.<ext>`

Examples:

- `fairy-wand__pink__identity__front__v01.jpg`
- `fairy-wand__pink__detail__card-slot__v01.jpg`
- `fairy-wand__pink__action-start__compartment-closed__v01.jpg`
- `fairy-wand__pink__action-end__card-inserted__v01.jpg`

Use the same name in the evidence ledger, prompt asset mapping, upload order, acceptance check, and failure record. Never rename an original file destructively; record aliases or create a copy only when a delivery package needs it.
